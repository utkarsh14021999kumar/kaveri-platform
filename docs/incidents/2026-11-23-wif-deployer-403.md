# RCA: Deployer WIF authentication 403 (drill #02)

- Date: 2026-11-23 to 2026-11-24
- Severity: P3 (non-production; no pipelines depended on the deployer)
- Tickets: #6 (acceptance), #9 (fix), #11 (change), #12 (debug/close-out)
- PRs: #7, #8 (smoke test), #10 (fix), #13 (temporary debug step)

## Summary
GitHub Actions jobs in environment dev could not impersonate the deployer service
account: 403 iam.serviceAccounts.getAccessToken. Plan identity and deny tests passed.

## Impact
Deployer path unusable from CI. No data exposure: the failure was fail-closed.

## Timeline
1. Smoke test: deployer-in-dev job returned 403 (STS exchange succeeded, impersonation failed).
2. Hypothesis: token subject does not match the deployer binding.
3. Evidence: repo OIDC customization API showed use_immutable_subject=true.
4. Fix (#9/PR #10): bind provider condition and bindings to numeric owner/repo IDs.
5. Admin apply (change #11), verified with gcloud.
6. First post-apply run still 403; re-run after ~3 minutes passed (IAM propagation).
7. Claims dump confirmed token sub matches the binding exactly.

## Root causes
1. Repository uses GitHub's immutable OIDC subject
   (repo:owner@OWNER_ID/repo@REPO_ID:environment:ENV); binding used the name-only format.
2. IAM propagation delay caused the first post-apply test to fail.

## Resolution
Provider condition and plan/deployer bindings use immutable numeric IDs.
This also prevents repo-jacking (trust cannot be inherited by a re-registered repo name).

## What went well
- Fail-closed behaviour; layered gates (plan gate, Terraform refused an incomplete plan).
- Evidence-first diagnosis; change record with independent verification.

## What went wrong
- PR #7 merged before checks ran (no required checks yet).
- A negative test initially passed for the wrong reason (empty variable).
- PR #10 body lacked plan evidence (/tmp wiped); corrected by PR comment.
- Interrupted plan; apply gate relied on log text instead of exit code.
